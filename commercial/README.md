# 商业许可模板包

[中文](README.md) | [English](README.en.md)

> 这些是运营和合同起草模板，不是法律意见，也不构成已经生效的授权。正式签署前，请让熟悉软件许可、未成年人监护和当地税务的律师审阅；方括号字段必须替换，未填写的模板不能直接发给客户。

## 适用结构

当前作者未成年时，推荐把关系写成：

- **作者 / 著作权人**：作者本人
- **授权方 / 签约方**：作者的监护人，作为法定代理人；如果监护人已有经营主体，也可以由该个体户或公司作为授权方
- **收款、开票、纳税**：授权方
- **客户**：购买商业许可的个人、公司或其他组织

不要由未成年人作为经营者注册个体户，也不要把监护人写成作者或把著作权直接转给监护人。合同、收款码、发票和授权证书应使用同一签约主体。

## 国际客户

GitHub 客户可能在境外，不能默认使用人民币、国内发票或国内个体户流程。跨境交易至少确认以下事项：

- **控制语言（主语言）**：跨境合同以英文版为准，中文版供作者和监护人内部审阅；如果客户要求双语，在订单表写明“英文版与其他语言冲突时以英文版为准”。
- **签约主体**：先确认客户是否接受监护人个人、个体工商户或公司签约。大型企业采购常要求公司主体、税号、银行账户、供应商准入、保险或 DPA；不能满足时不要假装是公司。
- **客户信息**：完整法定名称、注册地/国家、税号/VAT/GST、账单联系人、签署人姓名/职务和授权证明。
- **币种与税务**：报价写清币种、含税/不含税、预扣税、银行手续费及承担方；跨境预扣税可约定 gross-up，具体由会计师确认。
- **税务表格**：美国客户可能要求 W-8BEN（个人/个体经营者）或 W-8BEN-E（实体）；欧盟/英国可能涉及 VAT reverse charge；其他国家按当地规则处理。
- **付款与发票**：使用与授权方一致的商业账户；发票/收据类型按实际能开具的来写，不要承诺无法提供的增值税专用发票。
- **合规**：确认出口管制、制裁名单、反商业贿赂和数据保护要求；涉及个人数据时另签 DPA，本模板包不包含 DPA。
- **管辖与签署**：填写适用法律、法院/仲裁机构、通知地址和电子签名方式，不能留空。

这些是运营检查，不是法律意见。首份跨境合同应由熟悉中国外汇/税务和目标国法律的律师、会计师审阅。

## 文件

- `guardian-authorization.template.md`：监护人代理作者签署商业许可的内部确认
- `commercial-license-agreement.template.md`：商业许可协议框架
- `order-form.template.md`：授权范围、费用和付款的订单表
- `license-certificate.template.md`：发给客户的一页授权证书
- `first-reply-email.template.md`：首次回复商业咨询的邮件
- `license-registry.template.csv`：许可证登记和续费台账

## 下发顺序

1. 在私密渠道确认使用方、场景、规模、是否修改/再分发/白标/托管，以及期限。
2. 填写订单表并报价；报价单注明“报价不构成授权”。
3. 双方签署商业许可协议，并确认监护人代理关系或经营主体授权链条。
4. 按合同收款、开票和处理税费。
5. 发放 PDF 授权证书、签署后的协议和交付记录；如果承诺私有仓库或更新权限，再单独开通。
6. 登记许可证编号和续费日期，不要把客户个人信息放进公开仓库。

## 证书格式

- 仓库中的源模板使用 Markdown，便于审阅和版本控制。
- 正式发给客户的证书使用 **PDF**：版式固定、可签署/盖章、可做数字签名，且比图片更适合采购归档。
- 跨境客户可以只发英文证书；如果同时提供中文或其他语言译本，在订单表写明控制语言。
- 如必须使用 Word 流程，可以保留 `.docx` 编辑母版，但最终交付仍导出 PDF。
- 不要把 JPG/PNG 作为唯一证书；它们不方便检索、校验和长期归档。

授权证书只是协议摘要，不能替代双方签署的商业许可协议。
